# SecOps Copilot

**复试作品 · 徐慧超** ｜ 选题：改善 SOC 告警处理体验

> 把重复的 SSH 暴力破解告警聚合成「安全事件」，先用确定性规则给出可解释的风险评分，再让 AI Agent 按需取证辅助判断，最后由分析师拍板并留痕。

## 作品速览

| 面向谁 | 解决什么 | 效果如何 |
|---|---|---|
| SOC 安全分析师（一线告警研判人员） | 每天大量重复、误报、上下文分散的告警。本作品只切一个具体问题：**重复的 SSH 暴力破解告警** —— 125 条模拟告警中 85 条 SSH 聚合成 13 个事件（压缩 84.7%），规则先给可解释评分，AI 按需查登录历史 / 授权工单取证，人最终拍板 | 用可复现合成数据集 + 隔离的 Ground Truth 做五层评估，指标全部来自真实运行产物：解析成功率 100%、压缩率 84.7%、规则 P=1.00 / R=0.33 / F1=0.50、2 次工具调用成功率 100%。**算不出来的一律留空**，不填漂亮数字 |

这是一个可交互的 Web Demo：5 个页面，可筛选告警、触发 AI 研判、提交人工审核、查看评估结果。

## 1. 问题：SOC 分析师的一天

分析师每天要处理 SIEM / IDS / WAF / EDR 产生的大量告警，三类问题最耗时间：

- **重复** —— 同一来源 IP 对同一资产短时间内的暴力破解，被拆成几十条独立告警，逐条看等于重复劳动。
- **误报** —— 成功登录、已授权运维等正常行为也会触发告警，单看一条无法区分。
- **上下文分散** —— 判断是否真实攻击需要翻登录历史、查资产重要性、核对运维工单，这些信息不在告警里。

**为什么只做 SSH 暴力破解告警**：与其铺一个面面俱到的平台，不如把一个高频问题做透。这类告警量大、模式清晰、可通过只读数据取证，能完整展示「聚合 → 规则 → AI 取证 → 人工决策」的闭环。其他类型（端口扫描 / SQL 注入 / 恶意软件）只做加载与展示，标注「策略待扩展」，不生成研判结论。

| 环节 | 改善前 | 改善后 |
|---|---|---|
| 重复告警 | 85 条 SSH 逐条处理 | 5 分钟窗口聚合为 13 个事件，**压缩 84.7%** |
| 判断依据 | 只有单条告警，上下文靠人工翻日志 | 规则特征 + AI Agent **按需**调用只读工具（登录历史、授权运维），参数严格绑定当前事件 |
| 结论可信度 | 靠经验，难复核 | 结构化报告 + 证据引用校验（无效的 Alert ID / Tool Call ID 一律剔除）+ 工具调用轨迹留痕 |
| 决策归属 | — | **AI 只给辅助判断，人工审核才能定结论**，记录可追加 |
| 模型不可用时 | — | 保留告警 / 规则结果，明确标注 AI 失败，不生成伪装的成功报告 |

## 2. 产品长什么样

处理链路：`125 条多类型告警加载与去重` → `SSH 策略聚合 + 特征提取 + 互斥规则评分（上限 100）` → `有界 ReAct Agent（≤2 轮 / ≤4 次调用 / 总超时 45s）` → `白名单只读工具取证 + 结构化输出校验` → `人工审核与评估`。

| 页面 | 能看到什么 |
|---|---|
| **态势总览** | 125 条告警 / 13 个事件的实时统计、风险分布、类型与类别图表、近期事件 |
| **告警与事件** | 原始告警 / 安全事件双 Tab，全量筛选与分页；告警详情含原始日志；未支持策略显示「策略待扩展」且无研判入口 |
| **事件详情与研判** | 特征网格、规则评分仪表盘与命中明细、Agent 工具调用轨迹、AI 报告（证据 / 建议 / 不确定性）、人工审核 |
| **审核记录** | 审核状态流转与记录追加 |
| **效果评估** | 五层指标卡、3×3 混淆矩阵、工具与证据指标、评估边界说明 |

**建议体验路径**：态势总览看整体规模 → 告警与事件对比「85 条告警 / 13 个事件」的压缩效果 → 打开任一 SSH 事件看特征与规则命中 → 点「触发 Agent 研判」观察真实工具调用与结构化报告 → 提交人工审核 → 在效果评估页查看指标如何产生。

界面截图见 `screenshots/`（6 张 1440 宽长图）；现场优先演示运行中的真实页面。

## 3. AI 在其中做什么

AI 不是用来替代分析师，而是补上「找上下文」这一步：

- **有界 ReAct Agent**：最多 2 轮、4 次工具调用，总耗时上限 45s；不会无限循环。
- **白名单只读工具**：`query_login_history`（登录历史）、`query_authorized_operations`（授权运维记录）。工具参数严格绑定当前事件的来源 IP、目标资产与时间窗口，模型无法访问任意资产或任意时间范围。
- **结构化输出 + 证据校验**：报告必须是严格 JSON；引用只能指向本次真实存在的告警 ID 或本次成功调用的工具轨迹 ID，无效引用会被剔除并标记。
- **人在回路**：AI 结论不直接修改审核状态，分析师通过人工审核定结论，所有操作留痕。
- **失败可解释**：工具失败 / 超时 / 模型异常都会保留失败轨迹并标注信息缺口，不会伪装成查询成功。Ground Truth 仅评估模块可访问，不进入 Agent 上下文、Prompt、工具参数或业务 API 响应。

## 4. 效果怎么衡量

**方法**：用可复现的合成数据集 + 隔离的 Ground Truth，按五层口径计算；只统计实际运行并成功保存的研判、工具轨迹和审核记录，不把单元测试中 Mock LLM 的输出算成成果。

> 以下为线上 `GET /api/evaluation` 快照（2026-11-19，`demo-v1`，8 个场景样本，模型 `Qwen/Qwen3-30B-A3B-Instruct-2507`）。运行期数据保存在内存，页面数值随体验操作实时变化。

| 层 | 指标 | 实测值 | 说明 |
|---|---|---|---|
| 数据质量 | 输入 / 解析成功 | 125 / 125（**100%**） | 必填字段完整率 100% |
| 聚合 | 85 → 13，压缩率 | **84.7%** | 聚合 P/R 因无独立关联标注 → `null` |
| 规则 | P / R / F1 | **1.00 / 0.33 / 0.50** | 阈值 `score ≥ 50`；6 样本中 `UNCERTAIN` 2 个单独计数、不混入二分类 |
| AI | 有效样本 / 准确率 | **1 / 1.00** | 混淆矩阵 `ATTACK→ATTACK=1`；样本量仅 1，只证明指标口径可跑通，不证明泛化能力 |
| Agent | 工具调用 / 成功率 / 参数有效率 | **2 次 / 100% / 100%** | `toolPlanF1=0.67`，平均耗时约 25.5s |
| 业务 | 审核样本 / 采纳率 / 修正率 | **1 / 0% / 100%** | 人工修正了 AI 结论，体现「AI 只辅助、人拍板」 |

**分母不可还原或需要人工标注的指标，返回 `null` 并标注原因，不用 1.0 凑数**：

| 指标 | 状态 | 原因 |
|---|---|---|
| 引用可追溯率 | `NOT_COMPUTABLE` | 过滤前引用总数未持久化，分母无法还原 |
| 证据语义支持率 | `NOT_EVALUATED` | 需人工抽样判定，本期未做 |
| 效率提升率 | `NOT_MEASURED` | 无人工研判计时基线 |
| 聚合 P / R | `null` | 缺少独立的「告警—事件」关联标注 |

**局限**：以上结果仅代表合成数据集测试，AI 样本量极小，不代表生产泛化效果；规则阈值与聚合窗口为演示设定。模型服务存在波动，极端情况下单次研判接近 45s 上限。

## 5. 数据与前提

- **生成方式**：`scripts/generate_fixtures.py` 按场景模板可复现生成（非随机），重复运行结果一致；产物为只读 JSON fixtures。未使用公开数据集。
- **规模**：125 条告警（SSH 85 条，其中 80 条绑定 8 个评估场景；其余 40 条为展示样本）、资产 6 条、历史登录 12 条、授权运维 3 条、Ground Truth 8 条。
- **全部数据为虚构**，使用文档示例地址段（`203.0.113.0/24`、`198.51.100.0/24`、`192.0.2.0/24`），不代表真实攻击或真实资产。
- **前提假设**：告警的 `alertType` / `category` 由数据源直接给出，不宣称具备 AI 告警分类能力；规则分数是 Demo 启发式，不代表真实攻击概率；5 分钟聚合窗口与 ≥50 高风险阈值为演示设定，可按真实 SOC 策略调整；登录历史、授权工单、资产库以只读 fixtures 模拟，不代表真实设备接入。

## 7. 运行方式与技术信息

### 环境

| 组件 | 版本 |
|---|---|
| JDK / Maven | 17+ / 3.9+ |
| Node / npm | 22+ / 10+ |
| Docker | Desktop（含 Compose v2），推荐 |

```bash
# 方式一：Docker（推荐，项目根目录执行）
docker compose up -d --build          # http://127.0.0.1:8080

# 方式二：本地开发
cd backend  && mvn spring-boot:run   # http://localhost:8080
cd frontend && npm install && npm run dev   # http://localhost:5173
```

- **模型密钥**：环境变量 `SECOPS_API_KEY`（兼容旧名 `SECOPS_COPILOT_API_KEY`），**仅由后端读取**，不写入前端、仓库、日志或任何响应体。接入硅基流动 / 轨迹流动 OpenAI 兼容协议，模型 `Qwen/Qwen3-30B-A3B-Instruct-2507`。
- **未配置密钥时**：`/api/health` 返回 `modelConfigured=false`，告警 / 事件 / 特征 / 规则 / 审核 / 评估仍可查看，AI 研判不可用，不会伪造结果。
- **公网访问**：`https://secops.eu.cc` 通过 Cloudflare Tunnel 连接到前端容器；前后端宿主机端口仅绑定 `127.0.0.1`。当前 Demo 无登录鉴权，可直接体验。
- **运行期数据全在内存**：应用或容器重启后，事件、AI 研判、工具轨迹、审核记录、评估结果全部重置，fixtures 重新加载。

### 技术栈与验证

后端 Java 17 / Spring Boot / Spring AI Alibaba（SDK 类型集中在 AI 适配层），前端 Vue 3 / TypeScript / Vite / Element Plus / ECharts；存储为只读 JSON fixtures + 内存 Repository。

| 验证项 | 结果 |
|---|---|
| `mvn -B test` | **72/72 通过**（0 失败 / 0 错误 / 0 跳过） |
| `mvn -B -Dtest=DashScopeLiveIT test` | **连跑 3 次通过**（29.96s / 23.06s / 31.54s）；真实模型普通调用 + Function Calling，产出 `VALID` 报告与 `SUCCESS` 工具轨迹 |
| `npm run build` | **通过**（`vue-tsc --noEmit` + `vite build`） |
| `docker compose` 实际部署 | 两容器 healthy，公网页面与 `/api/health` 已实测可访问 |

**范围边界**：只注册 `SSH_BRUTE_FORCE` 策略；不实现真实安全设备接入、自动封禁 / 隔离、Multi-Agent、完整 RAG、MySQL / Redis / MQ、微服务、权限系统。

**已知限制**：引用可追溯率、语义支持率与效率提升率本期不可计算（见第 4 节）；前端主 chunk 约 2.2 MB（Element Plus + ECharts 全量引入），非阻断；尚无完整浏览器端到端自动化测试，公网页面已做浏览器烟测；AI 结论仍需人工复核。
