## 0. 演示前必读：诚实性约定

核心原则是 **「不把 Mock / 静态数据说成真实模型调用」**。当前真实闭环已跑通，但仍须遵守：

| 可以说 | 不可以说 |
|---|---|
| 告警加载、聚合、特征、规则评分、筛选、审核、评估指标是**后端真实计算** | 把单元测试里 Mock LLM 驱动的工具结果说成「现场演示成果」 |
| 独立集成测试曾真实执行 `query_login_history`；现场研判由模型按需决定工具，实际调用以本次 `SUCCESS` 轨迹为准 | 「集成测试的结果已经存进评估页」——集成测试不写运行期 Repository，评估页数值需现场触发后才产生 |
| 评估页 `null / 未测量 / 不可计算` 是**按口径如实留空** | 用任何硬编码准确率填空 |
| 模型不可用时系统**优雅失败并保留规则结果** | 展示任何伪装的成功 AI 报告 |

**现场若被问到「AI 到底跑通没有」**：答「跑通了。密钥属于硅基流动 / 轨迹流动平台（OpenAI 兼容协议），我新增了适配层并选了 Qwen3-30B 指令版；独立集成测试 `DashScopeLiveIT` 通过，产出的报告 `validationStatus=VALID`、工具轨迹 `SUCCESS`。现在页面上点研判会再真实执行一次。」详见第 6 节。

> 演示前请确认运行容器是最新构建，后端已注入 `SECOPS_API_KEY`，且 `/api/health` 返回 `modelConfigured=true`。该字段只表示密钥存在；先对拟演示事件实际触发研判，确认本次报告与工具轨迹。

## 1. 一句话讲清「帮助谁解决了什么问题」

> **帮助谁**：SOC 安全分析师。
> **什么问题**：SIEM / IDS / WAF / EDR 每天产生大量告警，其中重复告警多、误报多、上下文分散，人工逐条研判成本高。
> **选的具体切口**：把重复的 SSH 暴力破解告警聚合成一个「安全事件」，用确定性规则先给出可解释的风险评分，再让 AI 按需取证辅助判断，最后由人拍板并留痕。
> **合理假设**（无需事先熟悉 SOC）：模拟数据里 `alertType` / `category` 由数据源直接给出，不宣称具备 AI 告警分类能力；规则分数是 Demo 启发式，不代表攻击概率。

## 2. 「如何判断这个方案有效」的讲解口径

按 `PRD.md` 第 6 节，分五层说明，并主动指出本期哪些**算不出来**：

1. **数据质量**：解析成功率、必填字段完整率 —— 由 `AlertFixtureLoader` 的真实加载报告算，可算。
2. **聚合**：85 条 SSH 告警压缩为 13 个事件，压缩率可算；聚合 P/R 因无独立关联标注，返回 `null`。
3. **规则**：以 `ruleRiskScore >= 50` 为高风险阈值，与 Ground Truth 的 `ATTACK` 比，算 P/R/F1；`UNCERTAIN` **单独计数**（`uncertainSampleCount`），不混入二分类。
4. **AI / Agent**：**只统计实际运行并成功保存的研判与真实工具轨迹**。现场触发研判后，评估页才会出现有效 AI 样本、混淆矩阵与 Agent 工具指标；未触发前为空，不硬凑。
5. **证据 / 业务**：引用可追溯率因「过滤前引用总数未持久化、分母不可还原」返回 `不可计算`，**不输出恒为 1.0 的漂亮数字**；语义支持率需人工抽样标 `NOT_EVALUATED`，效率提升率无人工计时标 `NOT_MEASURED`。

> 结论话术：**「我用可复现的合成数据集 + 隔离的 Ground Truth 做评估，能算的指标全部来自真实运行产物；算不出来的一律留空并标注原因，而不是填一个好看的数字。」** 所有结果仅代表合成数据集测试，不代表生产泛化效果。

## 3. 环境准备（演示前 5 分钟做完）

```bash
# 方式一：本地（推荐，最稳）
cd backend  && mvn spring-boot:run      # http://localhost:8080
cd frontend && npm run dev              # http://localhost:5173

# 方式二：Docker Compose
docker compose up -d --build   # http://localhost:8080
```

- 环境变量 **`SECOPS_API_KEY`**（硅基流动 / 轨迹流动平台，OpenAI 兼容协议）：**只由后端读取**；兼容旧名 `SECOPS_COPILOT_API_KEY`。默认模型 `Qwen/Qwen3-30B-A3B-Instruct-2507`，配置见 `backend/src/main/resources/application.yml`。
- 运行期数据全在内存，**重启后事件、AI 研判、工具轨迹、审核记录、评估结果全部重置**；演示前建议重启一次，从干净状态开始。
- 打开 `http://localhost:8080`（或 5173），确认 `/api/health` 返回 `UP`、`mockDataLoaded=true`、`modelConfigured=true`。
- **预检**：选择拟演示的 SSH 事件，点「触发 Agent 研判」，检查报告及本次工具轨迹。模型可以直接回答；只有实际出现 `SUCCESS` 轨迹时才讲工具执行。若返回 503，切换到第 5 节路线 B。

触发条件：预检研判返回 503 / `ANALYSIS_FAILED`（断网、密钥失效、平台限流）。**此时如实说明模型不可用，不展示任何 AI 成功画面。**

| 时间 | 动作 | 讲解要点 |
|---|---|---|
| 0–3 | 背景 + `/status` | 「密钥存在只代表配置过；本次模型服务不可用，走降级路线，不伪造 AI 结果。」 |
